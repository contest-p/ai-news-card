# 프론트엔드 구현 보완 — 2026-10-08

바닐라 HTML/CSS/JavaScript 스택과 기존 화면 디자인을 유지하면서 새 백엔드 기능을 연결했다. 백엔드 변경은 한글 커밋 `52c2166`으로 origin/main에 푸시했다. 이번 프론트 변경은 아직 커밋하지 않았다.

## 구현한 기능

- 구독 관리에 관심 분야·키워드·수신 시간 변경 폼을 추가했다. 현재 설정과 서버가 반환한 다음 적용 설정/적용일을 구분한다. 변경 요청은 구독 ID와 expected_settings_version을 함께 보내며 구독 기간을 보내지 않는다.
- 저장 실패·버전 충돌에는 편집한 설정을 유지한다. 충돌 시 최신 설정 불러오기 버튼으로 다시 확인한 뒤 저장한다. 서버가 공개한 분야만 선택할 수 있고 공개 목록이 비면 신청/변경을 막는다.
- 해제 확인창을 열 때 구독 ID를 고정하고 `POST /subscriptions/{id}/cancel`에 confirm:true를 보낸다. 해제 확정 전에 화면 진입만으로 취소 요청하지 않는다. 중복 클릭 방지, Escape 닫기, 키보드 초점 순환을 추가했다.
- 개인정보 안내에서 `/account`로 연결한다. 로그인한 본인이 삭제 내용을 체크한 뒤 확인 POST를 보내고, 접수 성공·발송 중단·처리 대기 상태를 표시한다. 현재 페이지 세션에서는 요청 ID로 본인 상태를 조회한다. 새로고침 후 사용자 동기화가 삭제 대기 오류를 반환하면 대기 상태를 안내하며, 요청 ID는 브라우저 저장소에 저장하지 않는다. 인증 계정 삭제 이후에는 상태 조회가 불가능함을 안내한다.
- 피드백 화면의 예시 뉴스 카드를 제거했다. 실제 메일 링크의 fragment만 토큰으로 읽고 즉시 주소에서 제거한다. 토큰·평가 초안은 메모리에만 보관하며 피드백 API는 Firebase 인증 헤더 없이 POST body로 호출한다.
- resolve는 기존 평가/이유/의견을 읽기만 한다. 기존 평가가 있으면 먼저 표시하고, 없으면 메일 up/down 초기 선택을 표시한다. 사용자가 제출 버튼을 눌러야 평가 POST를 보낸다. 백엔드의 안정된 이유 코드를 사용하고 최대 5개·의견 500자를 적용한다.
- 피드백 일시 장애에는 링크와 의견을 유지해 재시도한다. 만료·잘못된 링크는 제출을 차단한다. 중복 제출과 이전 링크의 늦은 응답이 새 링크 상태를 덮는 문제를 막았다. 화면을 떠나면 메모리의 링크와 의견을 제거한다.
- 피드백으로 직접 진입하거나 브라우저 히스토리로 들어오는 경우 모두 링크를 처리한다. 직접 진입 시 외부 Firebase SDK를 초기화하지 않고 외부 추적/분석 리소스도 추가하지 않았다.
- 동의 버전이 바뀌면 기존 동의를 취소하고 다시 확인하게 한다. 개인정보 안내는 로그인 전에도 읽을 수 있다. 로그인 후 계정 삭제 등 원래 방문한 보호 화면으로 복귀한다.
- 완료 화면은 서버의 날짜와 설정을 표시하고 오래된 구독을 재조회했을 때도 '내일 첫 메일'이라고 단정하지 않는다. 구독 관리의 시작 날짜는 시간 변경 후에도 날짜로 표시한다.
- 모바일 설정/평가 폼, 키보드 초점 표시와 입력 라벨을 보완했다. 정적 자산은 절대 경로로 읽어 하위 URL/끝 슬래시에서도 로딩되게 했다.
- 서비스 소개에서 핵심 1장/최대 길이 2장 가상 샘플을 선택할 수 있다. 최대 샘플은 제목 60자, 각 설명 400자, 핵심 카드 용어 2개/풀이 각 100자를 포함한다. 배경 카드의 과거 날짜와 AI 표시를 유지한다. 출처 링크는 인증 정보 없는 HTTPS만 허용한다.

## API 연결

기존 `/users/sync`, `/subscriptions/save`, `/subscriptions/me`는 유지한다. 새 경로는 `/subscriptions/{id}/settings`, `/subscriptions/{id}/cancel`, `/feedback/resolve`, `/feedback`, `/account-deletion-requests`다. 개인정보와 보호된 요청은 Firebase ID Token을 매번 읽고 401이면 한 번만 갱신한다. 계정이 바뀐 요청의 결과를 다른 사용자 상태로 적용하지 않는다.

Backend의 `PUBLIC_CATEGORIES`가 비어 있으면 공개 가능한 분야가 없는 상태를 표시한다. 실제 QA 승인 없이 여섯 분야를 임의로 활성화하지 않았다. Backend의 설정 변경 capability가 true인 경우에만 변경 폼을 제공한다. 백엔드 요청/응답 상세는 `backend/BACKEND_COMPLETION.md`를 따른다.

## 로컬 검증

```powershell
node --test frontend/tests/*.test.cjs
# 로컬 정적 빌드: 실제 배포나 백엔드 호출 없음
$env:BACKEND_API_URL='https://api.example.invalid'
node frontend/tools/build.cjs
```

프론트 테스트 26개와 위 가상 HTTPS origin의 정적 빌드가 통과했다. 가상 HTTP·가상 Firebase·가상 DOM으로 설정 충돌, 구독 ID 확인, 동의 버전, 중복 요청, fragment 제거, 기존 평가, 일시 장애/만료, 이전 요청 경합과 카드 데이터/텍스트 escaping을 검증했다. dist는 Git 제외 대상이다.

실제 배포, 실제 계정/API·삭제·메일 QA, 브라우저/모바일 시각 검수와 메일 앱 fragment 보존 확인은 실행하지 않았다. 카드 데이터가 끝까지 렌더링되는 코드 검증은 실제 이미지 가독성 검수를 대신하지 않는다. 개인정보 안내 초안의 최종 승인, 서버 권한·보관 정책 적용, 승인 공개 분야, 배포 API origin 설정은 운영 단계에서 확인해야 한다.
