## 오늘 구현한 범위

`mail_assembly.py`에서 `assemble_mail()`은 3종 입력을 받습니다. 조립만 수행하며 메일 전송·DB 변경·토큰 발급은 하지 않습니다.

- 뉴스: 기존 카드·CID·텍스트·AI/출처 표시를 유지하고, 전달받은 토큰으로 `/feedback#t=...&rating=up|down`을 만듭니다. 토큰을 query에 넣거나 평가를 저장하지 않습니다.
- 뉴스 없음: 수집 성공과 `SelectionResult("no_candidates", None, None)`이 모두 필요합니다. 수집 실패·부분 실패·발송 부적격·AI 실패를 정상 뉴스 없음으로 바꾸지 않습니다.
- 종료: `expired`, 7/14/28일 기간, 만료 날짜와 안내 기준 날짜 일치를 검사합니다. cancelled/active/deletion_requested는 거부합니다. 발송 직전 최신 상태와 24시간 기한 검사는 향후 배치 책임입니다.
- 웹 링크: 운영자가 설정한 HTTPS origin으로 현재 Frontend의 `/manage`, `/feedback` 경로를 구성합니다. 외부 입력이나 AI가 만든 주소를 설정값으로 사용하지 않습니다.
- `preview=False` 뉴스는 웹 설정·피드백 토큰 누락을 거부합니다. 기존 데모 호환을 위해 기본값은 `preview=True`이며 검수 표시가 붙습니다. 이 플래그는 발송 허가가 아닙니다.
- 토큰과 이메일은 dataclass repr에서 제외합니다. `asdict()`·완성 MIME에는 값이 포함될 수 있으므로 운영 로그에 덤프하지 않습니다.

## 검증 결과

- 엔진 자동 테스트 **139개 통과**. 신규 메일 유형 테스트 11개 포함.
- 뉴스·뉴스 없음·종료의 가상 MIME/HTML/text 생성 성공.
- 로컬 Chromium에서 800px·390px, 각 유형의 기본/이미지 없는 미리보기 총 12개 화면 검사 통과: 가로 넘침 없음, 외부 요청 0, 기대 본문 표시.
- 모바일 3종 스크린샷을 직접 확인했습니다. 이번 뉴스 표본은 이미지 없는 전체 설명입니다. CID 첨부는 기존 자동 테스트로 확인했으며 실제 Gmail·모바일 메일 앱 검증은 하지 않았습니다.
- 실제 DB·AI·SMTP 호출 없음. 임베딩 모델 실다운로드/추론 검증도 이번 범위가 아닙니다.

이번 PC에는 기본 패키지가 없어 Git 제외된 `engine/.venv/`에 기존 고정 의존성을 설치했습니다. 전역 Python 패키지·의존성 버전 파일은 변경하지 않았습니다.

```powershell
.\engine\.venv\Scripts\python.exe -B -m unittest discover -s engine/tests
.\engine\.venv\Scripts\python.exe -B -m engine.demos.mail_types_demo
```

샘플 입력은 `engine/samples/mail.json`과 기존 rag/cards.json입니다. 생성 결과는 `engine/.engine-local/previews/mail-types/`에만 모읍니다. 이 새 미리보기 하위 폴더는 상태 기록을 담지 않으므로 검수 후 삭제하고 다시 생성할 수 있습니다. 기존 저장소 루트 `.engine-local/`의 생성·SMTP 기록과 구분합니다.

## 내일 DB 연결 시 필요한 계약

1. Backend에서 날짜별 구독 스냅샷, 사용자 전체 구독의 7일 sent/unknown 이력, 최신 해제·만료·삭제 요청 여부를 받습니다.
2. 뉴스용 `issue_feedback_token(job_id)`의 원문 토큰을 메일 조립에 전달합니다. 같은 작업 재시도 시 기존 토큰·내용을 어떻게 유지할지 합의합니다. 엔진에서 임의 토큰을 발급하지 않습니다.
3. 기사·내용 버전·임베딩 저장/검색을 연결합니다. 현재 `list_current()` 개발용 전체 조회를 운영 검색으로 사용하지 않습니다.
4. 엔진이 발송 작업/생성 작업의 트랜잭션·고정 ID·선점/횟수 코드를 구현하고 Backend가 스키마·권한·인덱스와 함께 리뷰합니다. 콜백 안에서 AI·SMTP 호출은 금지합니다.
5. 자연 만료 종료 안내는 일반 active 뉴스 대상과 별도 조회가 필요합니다. 수동 해제·삭제 요청은 제외하고 기존 구독 ID와 재구독 ID를 구분합니다.
