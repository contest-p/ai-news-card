# 엔진 구조와 다음 정리 기준

2026-10-06: 코드 내용 변경 없이 설치 목록과 Firestore 자료를 분리했습니다.

## 위치별 용도

| 위치 | 용도 | 보관 기준 |
|---|---|---|
| engine 루트의 .py | 기능 구현과 공용 자료형 | 서비스 코드 |
| demos/ | 기능별 샘플·실제 연결 실행 | 개발·시연용; 다른 코드의 참조 확인 후 정리 |
| tools/ | 이미지 렌더러·레이아웃 검사·SMTP 테스트 | 운영에 쓰는 도구와 검수 도구가 함께 있으므로 통째 삭제 금지 |
| tests/ | 자동 회귀 테스트와 코드 내부 가상 데이터 | 완성 후에도 보관 |
| samples/ | 가상 기사·구독·RSS·AI 응답 | 테스트에서도 참조하므로 보관 |
| templates/ | 현재 렌더러가 읽는 임시 카드 디자인 | 최종 템플릿 연결 후 교체 여부 판단 |
| dependencies/ | Python 의존성과 잠금 파일 4개 | 함께 보관; 파일 간 상대 참조 유지 |
| docs/ | 실행 안내·검수·개발 기록 | 과거 기록과 현재 상태를 구분 |
| docs/firebase/ | Firestore 안내·변경 기록·규칙 조각 | Backend 협업 자료 |

`package.json`과 `package-lock.json`은 Node 렌더러의 의존성 설치 위치 때문에 engine 루트에 유지합니다. `.env.example` 역시 현재 설정 로더가 사용하는 위치의 안내입니다.

## 이번에 Python 파일을 이동하지 않은 이유

코드 수정 금지 조건을 지키기 위해 기존 import와 실행 경로를 유지했습니다. 파일만 이동해도 `engine.selection` 같은 import, `engine.chat_worker` 자식 프로세스 실행, `__file__` 기준 샘플·템플릿 경로가 깨집니다. 이 구조 안내가 현재 역할별 탐색 기준입니다.

프로젝트 완성 후 코드 경로 수정까지 허용되는 정리에서는 수집·저장·검색·생성·렌더링·메일별 패키지 분리를 검토합니다. 파일 이동과 import·CLI·리소스 경로·문서 변경을 함께 수행하고 기존 테스트를 확인해야 합니다.

특히 `tools/smtp_test.py`는 `demos/mail_demo.py`를 참조하고, 여러 테스트는 다른 테스트 파일의 준비 데이터를 공유합니다. demos나 tests를 독립된 임시 폴더처럼 삭제하면 안 됩니다.

## 실행 결과와 상태 기록

실행 결과는 코드상 저장소 루트 `.engine-local/`에 저장합니다. 이번 정리 시 해당 폴더는 없었고 새로 만들거나 이동하지 않았습니다.

- 카드 PNG·HTML·메일 미리보기·검수 보고서: 필요할 때 생성하고 검수 종료 후 정리할 대상입니다.
- 실제 수집 기사·AI 응답: 가상 샘플과 구별하며 재검수에 필요한지 확인합니다.
- 생성 작업·호출 횟수·SMTP 전송 상태: 단순 미리보기가 아닙니다. 재호출·중복 전송 방지에 사용하므로 일괄 삭제하지 않습니다.

향후에는 미리보기 출력과 상태 기록을 서로 다른 경로로 분리하는 것이 좋습니다. 이번에는 코드 변경이 필요한 출력 경로 변경을 하지 않았습니다.
