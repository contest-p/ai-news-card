# 정각 발송을 위한 사전 준비

외부 예약에서 매시간 한국 시간 50분에 Actions를 호출하면 다음 정각까지 환경 설치와 기사 수집을 진행한다. 수집을 일찍 마치면 목표 정각까지 기다린 뒤 구독 대상 조회, 개인별 AI 생성, 이미지 렌더링, SMTP 발송을 시작한다. 정각 수신을 보장하지는 않는다.

## cron-job.org 설정

- 예약: Asia/Seoul 기준 매시간 50분(`50 * * * *`). 55분도 가능하지만 준비 시간이 부족할 수 있다.
- HTTP 메서드: POST
- URL: `https://api.github.com/repos/contest-p/ai-news-card/actions/workflows/engine-mail.yml/dispatches`
- 헤더: `Accept: application/vnd.github+json`, `Content-Type: application/json`, `Authorization: Bearer <발급한 토큰>`
- 토큰: 해당 저장소만 선택한 fine-grained 토큰, Actions 쓰기 권한. 토큰은 Git이나 문서에 저장하지 않는다.
- 요청 본문:

```json
{"ref":"main","inputs":{"mode":"run","delivery_at":"hourly"}}
```

`hourly`는 GitHub가 워크플로를 생성한 시각의 다음 정각으로 변환한다. 실행기가 늦게 시작해도 생성 시각으로 고정한 목표를 사용하므로 다음 시간까지 다시 기다리지 않는다. 워크플로 재실행도 원래 목표를 사용한다. 요청 자체가 다음 시간으로 넘어가서 접수되면 다음 정각으로 해석되므로, 정각 이후 자동 재요청에는 hourly를 사용하지 않는다.

특정 시각을 확정하고 싶으면 `delivery_at`에 `2026-10-10T08:00:00+09:00`처럼 날짜와 시간대를 포함한 값을 전달한다. 이 값은 매일 바뀌므로 반복 예약에는 hourly를 사용한다. 빈 값은 기존처럼 즉시 조회한다. 수동 Run workflow도 같은 입력을 제공한다.

외부 예약 등록은 코드 푸시와 별개로 cron-job.org 계정에서 수행해야 한다. 외부 예약을 등록하기 전에는 기존 방식으로만 실행된다. 호출 성공은 GitHub의 요청 접수이며 실제 발송 성공이 아니다. 외부 호출 실패 알림과 Actions 실행 결과, Firestore `sent_at`을 함께 확인한다.

## 기존 예약과 제한

기존 매시간 7분 GitHub 예약은 지연·실패 복구용으로 유지한다. 예약 활성화에는 기존 `ENGINE_SCHEDULE_ENABLED=true`가 필요하다. 외부 수동 호출은 이 변수와 무관하게 실행된다. 동시 실행 제한과 고정 작업 ID가 중복 발송을 방지한다. 복구 예약이 선점하면 외부 실행이 기다릴 수 있다.

대기는 기사 수집 다음, 대상 조회 직전에 수행한다. 이미 목표 시간이 지났으면 대기 없이 처리한다. 대기는 45분 처리 예산에서 제외하며 workflow 전체 제한은 기존 75분이다. CLI 시작 시 목표가 20분보다 먼 미래면 잘못된 장시간 대기를 차단한다.

사용자별 AI 생성·렌더링은 정각 이후 순서대로 진행한다. 발송 직전 해제·만료 검사는 유지한다. 설치·수집이 길어지거나 실행 대기가 생기면 정각보다 늦게 발송될 수 있다. 기사 수집은 기존 최대 15분 예산을 유지한다.
