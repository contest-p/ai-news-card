# 김현서 — Frontend PRD

## 목표
사용자가 서비스를 이해하고, 로그인·구독·관리·피드백을 쉽게 할 수 있는 화면과 뉴스 카드 디자인 만들기.

## 고정 기술스택
- 바닐라 HTML/CSS/JavaScript: 화면. React·Next.js 등으로 변경하지 않기
- Vercel: 웹 배포 / Supabase Auth + Google: 로그인·로그아웃
- HTML/CSS + 로컬 폰트: 카드 템플릿. 이미지 변환은 박경연이 Playwright/Chromium으로 연결
- 서버 연결: 고승희가 만드는 FastAPI 사용

## 만들 것
1. **서비스 소개 화면 만들기.** 관심 뉴스의 핵심과 배경을 카드로 설명해주는 서비스임을 알리고, 로그인·구독 시작 버튼 넣기.
2. **로그인·로그아웃 기능 만들기.** Google·Supabase 로그인 연결, 필요한 콘솔 설정, 로그인 취소·실패 안내까지 만들기.
3. **개인정보 안내·동의 화면 만들기.** 고승희와 박경연이 정리한 문구를 보여주고, 동의 후 구독할 수 있게 하기.
4. **구독 설정 화면 만들기.** 공개된 관심 분야, 키워드, 수신 시간, 1주·2주·4주 기간을 선택하고 서버에 저장하기. 저장 후 첫 발송 시각과 마지막 구독 날짜 보여주기.
5. **구독 관리 화면 만들기.** 현재 설정과 다음 날 적용할 설정을 보여주고, 설정 변경·해제·재구독 제공하기.
6. **피드백 화면 만들기.** 메일에서 들어온 사용자가 평가와 짧은 의견을 확인 후 제출할 수 있게 하기.
7. **뉴스 카드 템플릿 만들기.** 핵심 카드 1장과 선택적인 배경 카드 1장을 샘플 데이터로 디자인하기. 제목·설명·용어·출처·AI 표시와 과거 정보의 시점 넣기.
8. **로딩·오류·모바일 화면 다듬기.** 서버 응답 대기, 저장 실패, 로그인 만료 등을 이해하기 쉽게 안내하고 휴대폰에서도 읽기 좋게 만들기.
9. **계정 삭제 요청 방법 안내하기.** 실제 요청 채널을 개인정보 안내에 표시하기.

## 꼭 지킬 것
- 구독 해제는 웹사이트에서 로그인·확인 후 실행. 메일 링크로 페이지에 들어오는 것만으로 해제하지 않기.
- 피드백 링크를 열기만 해서는 평가를 저장하지 않기. 링크의 토큰은 서버에 안전하게 전달하고 주소·저장소·로그에 남기지 않기. 이 화면에 외부 추적 도구를 넣지 않기.
- 제목 60자, 카드별 설명 400자, 용어 2개·풀이 각 100자를 동시에 채워도 이미지가 잘리거나 겹치지 않고 모바일에서 읽혀야 함.
- 첫날·마지막 날 등 날짜와 최종 키워드 처리 결과는 서버 응답을 사용하기. 저장 실패를 성공으로 표시하지 않기.
- 화면 로그인은 김현서, 서버 권한 확인은 고승희. 카드 디자인은 김현서, 이미지 변환·메일 본문은 박경연 담당.

## 받아서 연결할 것
- 고승희: API와 성공·실패 샘플, 개인정보 안내 문구, 공개 분야 목록
- 박경연: 카드 데이터와 최대 길이 샘플, 이미지 변환 연결 방식
- 윤지민: 배포 주소와 모바일·메일 검수 결과

## 나중에 해도 되는 것
별도의 계정 삭제 신청 화면. 생략해도 실제 요청 방법 안내는 유지하기.

## 완료 모습
사용자가 휴대폰에서 로그인 → 구독 → 설정 변경·해제 → 피드백까지 할 수 있고, 샘플 카드가 최대 길이에서도 읽기 좋게 표시됨.

## AI에 작업을 맡길 때
이 PRD와 공통 PRD를 함께 전달하고, 위 기능을 작은 단위로 구현해 달라고 요청하기. 구현 방식은 AI가 제안하되 고정 기술스택과 담당 경계는 유지하기. 다른 담당자와 주고받는 데이터는 샘플을 먼저 공유하기.

> 이 문서는 쉬운 작업 안내다. 상세 날짜·보안·발송 정책은 공통 PRD v0.3을 따른다. 충돌하거나 정하지 않은 부분은 임의로 바꾸지 않고 팀에 확인한다. 일정·마일스톤은 포함하지 않는다.
