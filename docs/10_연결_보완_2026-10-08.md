# 엔진·백엔드·프론트 연결 보완

2026-10-08. 연결 검토에서 확인한 네 항목을 보완했다. 배포·실서비스 QA·실제 개인정보 삭제는 수행하지 않았다.

| 항목 | 변경된 동작 |
|---|---|
| 운영·테스트 작업 ID 충돌 | 피드백 발급 요청에 environment를 추가했다. 생략하면 production이며 테스트 배치는 test를 명시한다. 각 발송 컬렉션만 조회하고 토큰·피드백 저장 ID도 분리한다. 기존 운영 토큰 계산과 저장 ID는 유지한다. |
| 개인정보 정리가 메일 설정에 종속 | 별도 engine.tools.privacy_cleanup 명령이 백엔드 정리 API만 호출한다. AI·SMTP·기사 저장소 설정이 없어도 실행 가능하다. 오류나 불완전 응답은 종료 코드 1로 반환하여 독립 예약 작업에서 재시도할 수 있다. |
| 과거 구독 문서 ID 호환 | 설정 변경 시 구독 ID와 인증 사용자 소유권으로 실제 문서를 찾아 같은 문서에 기록한다. 문서 ID가 uid와 다른 구독 및 subscription_id 필드가 없는 문서의 ID 대체값을 지원한다. 다른 사용자 문서는 404, 중복 구독 ID는 409다. 현재 구독 조회도 같은 과거 문서를 지원한다. |
| 신청 성공 후 조회 일시 실패 | 완료 화면에서 재조회가 네트워크 오류 또는 5xx로 실패하면 저장 응답의 활성 구독을 유지하고 안내·재조회 버튼을 표시한다. 재시도에서도 같은 정책을 적용한다. 401·404 및 계정 변경 시에는 이전 구독을 유지하지 않는다. |

## 개인정보 정리 실행

저장소 루트에서 실행한다. ENGINE_API_BASE_URL은 엔진 전용 prefix 전체이며 ENGINE_API_TOKEN은 백엔드와 동일한 32자 이상의 서버 인증 키다. engine/.env 또는 실행 환경에서 제공한다.

```powershell
# 로컬 설정 확인만 수행하며 네트워크·AI·SMTP를 호출하지 않는다.
.\engine\.venv\Scripts\python.exe -B -m engine.tools.privacy_cleanup --check

# 명시적으로 실행할 때 실제 백엔드의 개인정보 정리 정책을 적용한다.
.\engine\.venv\Scripts\python.exe -B -m engine.tools.privacy_cleanup --run
```

실제 예약 적용 시 메일 발송 작업과 별개의 주기적 작업으로 --run을 등록하고 실패 시 재시도해야 한다. 기존 백엔드 삭제 정책·처리량 제한·재시도 상태를 그대로 사용한다. 예약 작업 활성화는 이번 범위에 포함하지 않았으며 이 명령을 실제 백엔드에 실행하지 않았다.

기존 구독에 동의 버전 등 필수 설정이 없다면 이를 임의로 만들어 내지 않는다. 이번 수정은 구독 문서를 uid 경로로 옮기는 마이그레이션을 요구하지 않으며 실제 DB에 마이그레이션을 실행하지 않았다.

## 로컬 검증

외부 API·실제 Firestore·SMTP를 호출하지 않는 테스트로 환경별 피드백 독립성, 과거 문서 설정 변경과 소유권·중복 보호, 개인정보 정리 독립 실행과 실패 처리, 완료 화면의 재조회 실패·재시도·계정 변경 처리를 검증했다.
