# 프로젝트 기획서 — AI 기반 개인화 뉴스 브리핑

- 작성·수정일: 2026-10-14
- 대상: 서면 평가자와 서비스 이용자
- 서비스: [뉴스 브리핑](https://ai-news-card-frontend.vercel.app)

## 1. 문제 정의

관심 뉴스를 매일 직접 찾고 여러 기사를 열어 핵심과 배경을 파악하는 데 시간이 든다. 제목이나 썸네일만으로 내용을 판단하면 기사 맥락을 놓치기 쉽다. 사용자가 원하는 주제를 선택하면 **원문 출처를 확인할 수 있는 짧은 뉴스 카드**를 이메일로 받아보게 하는 것이 이 프로젝트의 목표다.

이 서비스는 원문 자체의 사실성을 완전히 판별하지 않는다. AI가 작성한 설명에는 출처와 원문 링크를 함께 제공하고, 생성물임을 표시한다.

## 2. 타깃 사용자와 이용 경험

**타깃:** 자신이 원하는 분야의 뉴스를 편리하게 받아보고 싶은 사람. 뉴스 수집·요약·발송 자동화를 직접 설정할 필요 없이, 관심 주제와 받는 시간만 정해 사용한다.

1. Google 계정으로 로그인하고 개인정보 안내에 동의한다.
2. 관심 분야, 선택 키워드, 한국 시간 기준 수신 시간, 구독 기간 1·2·4주 중 하나를 고른다.
3. 구독 직후 미리보기를 요청할 수 있으며, 정기 브리핑은 가입 다음 날부터 이메일로 받는다.
4. 메일에서 핵심 카드와 조건에 맞는 경우 배경 카드를 읽고 원문을 확인한다. 웹에서 설정 변경·구독 해제, 메일 링크에서 피드백을 제출할 수 있다.

구독 기간은 첫 정기 발송일을 포함한 7·14·28일이다. 설정 변경은 다음 날 적용된다. 발송·도착 시각은 외부 서비스 상태에 따라 지연될 수 있다.

## 3. AI 활용 방식

생성형 AI는 부가 기능이 아니라 **뉴스를 읽기 쉬운 카드로 만드는 핵심 기능**이다.

| 단계 | 처리 | 결과 |
|---|---|---|
| 수집·선별 | RSS 기사 본문과 게시 시각을 확인하고 관심 분야·키워드에 맞는 기사를 고른다. | 오늘의 기사 |
| RAG | 같은 분야의 유효한 과거 기사를 E5 임베딩과 Firestore 벡터 검색으로 찾는다. | 배경 카드에 쓸 근거 |
| 생성·검사 | 기사와 검색 근거를 AI에 제공해 카드 JSON을 만들고 구조·발췌·수치·시점·출처를 검사한다. | 핵심 카드 1장, 근거가 충분하면 배경 카드 1장 |
| 렌더링·전달 | 검사를 통과한 내용을 고정 템플릿 이미지와 텍스트 메일로 조립한다. | AI 표시·원문 링크가 포함된 이메일 |

배경 근거가 없거나 검사에 실패하면 배경 카드는 생략한다. 영어 기사로 만든 카드 내용은 한국어 변환 단계를 거친다. 생성형 이미지로 카드 전체를 그리거나, 채팅·음성·다중 Agent를 제공하는 것은 이번 범위에 포함하지 않았다.

## 4. 기술적 접근

```text
사용자 → Vercel 웹 → Firebase Google 로그인 → FastAPI 구독 API → Firestore
RSS → GitHub Actions의 Python 엔진 → 기사 선별·RAG → AI 카드 생성·검사
    → Playwright 카드 렌더링 → Gmail SMTP → 사용자 이메일·피드백
```

| 영역 | 선택 기술 | 선택 이유 |
|---|---|---|
| 웹·API | HTML/CSS/JavaScript, Vercel, FastAPI | 구독 설정과 관리 화면을 공개 웹·API로 제공 |
| 인증·데이터 | Firebase Authentication, Cloud Firestore | Google 로그인, 구독·기사·발송 이력 관리, 과거 기사 벡터 검색 |
| 자동 실행 | GitHub Actions, Python | 수집부터 생성·발송까지 정기 배치로 연결 |
| AI·이미지 | Chat Completions 호환 API, multilingual-e5-small, Playwright | 근거 검색과 구조화된 설명을 만들고 고정 템플릿으로 렌더링 |
| 메일 | Gmail SMTP | 개인별 브리핑과 안내 메일 전달 |

발송 작업 ID와 상태를 저장해 재실행 중복 발송을 막고, 결과가 불확실한 SMTP 전송은 자동 재전송하지 않는다. 개인정보 동의, 본인 확인, 계정 삭제 요청과 보관 기한 정리는 별도 흐름으로 관리한다. 기술별 입력·예외·한도와 Must/Should 전체 목록은 [요구사항 정의서](REQUIREMENTS.md)에 두었다.
