# 고승희 — Backend·DB PRD

## 목표
사용자·구독·피드백 정보를 안전하게 저장하고, 화면과 뉴스 엔진이 사용할 기능 만들기.

## 고정 기술스택
- Python + FastAPI: 서버 기능 / Render: 서버 배포
- Supabase PostgreSQL: DB / Supabase Auth + Google: 로그인 확인
- Gmail SMTP: 발송 계정 준비·연결 테스트. 실제 서비스 발송 코드는 박경연 담당

## 만들 것
1. **로그인한 사용자 확인 기능 만들기.** Google·Supabase 로그인 정보를 확인하고, 본인 정보만 조회·수정할 수 있게 하기. 로그인·로그아웃 버튼과 화면은 김현서 담당.
2. **사용자·구독·피드백 DB 만들기.** 필요한 정보를 저장하고, DB 변경 사항을 팀 전체에서 같은 순서로 적용할 수 있게 관리하기.
3. **구독 생성 기능 만들기.** 관심 분야, 키워드, 수신 시간, 1주·2주·4주 기간, 개인정보 동의를 저장하기. 같은 사용자의 활성 구독이 중복 생성되지 않게 하기.
4. **구독 날짜 기능 만들기.** 가입 다음 날부터 선택한 기간 동안 발송하도록 첫날·마지막 날·만료일 계산하기.
5. **구독 조회·변경·해제·재구독 기능 만들기.** 현재 설정과 다음 날 적용할 설정을 구분하고, 웹사이트에서 본인이 해제할 수 있게 하기. 만료·해제 후에는 새 구독을 만들 수 있게 하기.
6. **엔진에 구독 정보 전달하기.** 박경연이 오늘의 대상·설정·수신 주소를 받고, 발송 직전에 구독이 유효한지 확인할 수 있게 하기.
7. **피드백 저장 기능 만들기.** 메일의 평가 링크를 확인하고, 사용자가 제출한 평가와 의견 저장하기. 링크를 열기만 했을 때는 평가하지 않기.
8. **개인정보 안내·정리·계정 삭제 처리 만들기.** 안내 문구 초안을 쓰고, 만료·해제 후 30일 이내 개인정보를 삭제하거나 개인을 알아볼 수 없게 바꾸기. 실제 계정 삭제 요청을 처리할 방법 마련하기.
9. **SMTP 계정 준비·테스트하기.** Gmail 계정과 발송 설정을 준비해 테스트 결과를 박경연에게 전달하기.
10. **팀 DB 변경 사항 합치기.** 박경연이 만든 발송·엔진 DB 코드를 리뷰하고 전체 DB에 반영하기.

## 꼭 지킬 것
- 다른 사람의 정보에 접근하지 못하게 서버와 DB에서 권한 검사하기. API 키·비밀번호·개인정보를 코드나 로그에 남기지 않기.
- 날짜는 한국 시간 기준. 기간은 1주·2주·4주이고, 설정 변경은 다음 날부터 적용. 기존 구독의 기간 변경은 제공하지 않기.
- 해제는 로그인한 본인이 웹에서 확인 후 실행. 해제·만료·계정 삭제 요청이 있으면 엔진의 발송 가능 확인에서 제외하기.
- 키워드의 최종 정리는 서버에서 담당하도록 연결 방식 합의하기. 피드백 토큰은 안전하게 처리하고 주소 쿼리나 로그에 남기지 않기.
- 개인정보 정리는 마감 전에 끝나도록 만들고, 실패하면 다시 처리할 수 있게 하기. 개인정보 안내 내용은 박경연의 최종 검토받기.

## 받아서 연결할 것
- 박경연: 발송·엔진 DB 코드와 엔진이 필요한 구독 정보
- 김현서: 화면에서 사용할 요청·응답 요구
- 윤지민: 배포 주소, 권한·동작 테스트 결과

## 나중에 해도 되는 것
별도의 계정 삭제 신청 화면·API. 다만 화면을 생략해도 실제 요청 채널과 본인 확인·삭제 처리 절차는 반드시 제공하기.

## 완료 모습
화면에서 구독을 만들고 바꾸고 해제할 수 있으며, 날짜·권한·피드백이 정상 처리되고 엔진이 정확한 구독 정보를 받아 사용함.

## AI에 작업을 맡길 때
이 PRD와 공통 PRD를 함께 전달하고, 위 기능을 작은 단위로 구현해 달라고 요청하기. 구현 방식은 AI가 제안하되 고정 기술스택과 담당 경계는 유지하기. 다른 담당자와 주고받는 데이터는 샘플을 먼저 공유하기.

> 이 문서는 쉬운 작업 안내다. 상세 날짜·보안·발송 정책은 공통 PRD v0.3을 따른다. 충돌하거나 정하지 않은 부분은 임의로 바꾸지 않고 팀에 확인한다. 일정·마일스톤은 포함하지 않는다.
