# 윤지민 — 배포·QA·데이터 검증 PRD

> 2026-10-05 Firebase 반영판(v0.3). 공통 PRD v0.4 기준이며 파일명은 기존 링크 유지를 위해 유지합니다.

## 목표
팀이 만든 서비스를 실제로 사용할 수 있게 배포하고, 뉴스·카드·사용 흐름에서 문제를 찾아 재확인하기.

## 고정 기술스택
- Vercel: 웹 배포 / Render: FastAPI 서버 배포
- Firebase: Cloud Firestore·Authentication 환경 / GitHub Actions: 자동 실행 환경
- Gmail SMTP·코디세이 API: 실제 발송·AI 연결 확인
- 카드 이미지: HTML/CSS + Playwright/Chromium 방식의 실행 환경 확인

## 할 것
1. **서비스 배포하기.** 웹·서버·자동 실행 환경을 준비하고, 외부 주소에서 접속·실행되게 하기.
2. **계정·권한·비밀 설정 확인하기.** 팀원이 필요한 환경에 접근할 수 있게 하고, 박경연이 설정·로그·복구에 접근할 수 있는지 확인하기. 서버 서비스 계정·API 비밀값은 서비스의 비밀 설정 기능에 등록하기. Firebase Google 공급자·허용 도메인, Firestore IAM·Security Rules·인덱스·사용량도 확인하기.
3. **뉴스 소스 검증하기.** RSS가 열리는지, 기사 날짜와 본문을 가져올 수 있는지, 실제 분야가 맞는지 확인해 통과·실패 목록 전달하기.
4. **RAG 검색 품질 확인하기.** 과거 기사 표본이 오늘 기사를 이해하는 데 도움이 되는지 표시해 박경연에게 전달하고, 조정 후 다시 확인하기.
5. **AI 카드 내용 확인하기.** 기사 원문과 카드의 수치·단위·대상·시점·증감 방향·출처가 맞는지 표본을 직접 대조하기.
6. **사용자 흐름과 오류 상황 테스트하기.** 가입·구독·날짜·설정 변경·해제·만료·피드백을 확인하고, 중복 실행·발송 중단·수집 실패·권한 오류도 확인하기.
7. **실제 메일과 카드 확인하기.** 모바일에서 최대 길이 카드가 읽히는지, 이미지가 차단돼도 설명이 보이는지, 출처·피드백·구독 관리 링크가 동작하는지 확인하기.
8. **사용자 테스트 진행하기.** 테스터 5명 이상을 모집해 사용과 설문을 진행하고, 문제·개선 의견을 모아 담당자에게 전달하기. 수정 후 다시 확인하기.
9. **운영 상태와 장기 구독 확인하기.** 자동 실행·실패·발송 상태를 점검하고, 2주·4주 구독이 끝날 때까지 API 키·메일·배포 환경을 유지할 수 있는지 확인하기.

## 꼭 지킬 것
- 문제가 있으면 재현 방법과 기대 결과·실제 결과를 기록하기. 코드 수정은 해당 기능 담당자가 하고, 윤지민이 수정 결과를 다시 확인하기.
- 박경연의 발송 코드와 김현서의 로그인 콘솔 설정을 대신 구현하지 않기. 필요한 환경과 검증 결과를 제공하기.
- 검증하지 않은 뉴스 분야는 공개 가능하다고 표시하지 않기. 외부 서비스의 한도·권한도 실제 확인 결과로 기록하기.
- 비밀번호·API 키·실제 사용자 개인정보를 문서·스크린샷·로그·GitHub에 올리지 않기. 직접 비밀 설정 등록 권한이 없으면 권한이 있는 박경연에게 등록 요청하기.
- 보냈는지 불확실한 메일을 임의로 재발송하지 않기. 발송 상태를 확인해 박경연에게 전달하기.

## 받아서 확인할 것
- 박경연: 엔진 실행·발송 기록, AI 카드, 복구 방법
- 고승희: API·DB·권한·개인정보 정리 기능
- 김현서: 웹 화면·로그인·카드 템플릿

## 나중에 해도 되는 것
비슷한 사건 자동 묶기의 검증은 해당 기능을 구현할 때 진행하기. 과거 기사 검색 품질과 AI 내용 검수는 유지하기.

## 완료 모습
외부 주소에서 사용자가 가입하고 메일을 받으며, 주요 오류 상황과 보안·가독성 검증 결과가 기록되고 사용자 의견에 따른 수정이 재확인됨.

## AI에 작업을 맡길 때
이 PRD와 공통 PRD를 함께 전달하고, 배포 설정·테스트 절차·결과 기록 양식을 작은 단위로 준비해 달라고 요청하기. 고정 기술스택과 담당 경계는 유지하고, 실제 검증하지 않은 항목을 완료로 기록하지 않기.

> 이 문서는 쉬운 작업 안내다. 상세 날짜·보안·발송 정책은 공통 PRD v0.4을 따른다. 충돌하거나 정하지 않은 부분은 임의로 바꾸지 않고 팀에 확인한다. 일정·마일스톤은 포함하지 않는다.
